# 设置注册表

设置前端、全局搜索、恢复默认、MCP 和[设置项参考](../guide/settings-reference.md)共用主仓的 [settings_catalog](https://github.com/weq-devs/WeQ/tree/dev/packages/service/src/common/settings_catalog)。它只保存公开定义，不读取账号、当前配置或宿主文件，浏览器可以直接导入。

## 定义与适配

- `navigation.ts` 定义稳定 ID、页面、分类、名称及旧入口重定向。`keywords.ts` 只补充按稳定 ID 关联的检索词，不独立声明设置成员。
- `fields.ts` 把恢复字段绑定到设置 ID、分区、作用域和现有默认值提供方。应用设置、共享偏好和 AI 参数分别引用原有默认配置，不复制默认值。
- `reset.ts` 提供恢复分区和差异规划器，页面恢复与兼容全局恢复共用目录选择、差异与重试筛选规则。`global.ts` 登记应用字段的全局恢复类别以及 API、连接和目录的保留策略。
- 桌面主进程的 `settings_reset.ts` 只提供真实读写适配器，继续调用原业务接口；预览和执行使用同一份字段定义。带账号或数据源的恢复仍核对来源，AI 关联参数仍成组提交。
- 渲染层恢复只请求宿主预览与执行，再接收共享偏好快照，不再另外维护前端恢复项。恢复前等待已经发出的偏好保存完成，避免迟到保存覆盖恢复结果。
- 复杂表单继续使用专用组件。普通 `Row` 可以只传注册表中的 `settingId`，由注册表提供名称；上下文相关名称仍允许显式传入。

全局配置重建仍通过原来的备份事务落盘，账号文件、运行连接和浏览器状态继续由相应适配器处理。「配置备份与恢复」页的全局恢复入口使用 `weq-config-management` 稳定 ID；页面恢复入口使用 `settings-reset-<page>`，不复用全局入口身份。共用目录、默认值与规划器不意味着绕过这些持久化流程。

## 新增或移动设置

1. 在目录中登记或复用稳定 ID，修改页面归属时保留必要的旧入口和搜索别名。
2. 可恢复的偏好在 `fields.ts` 登记字段，使用已有默认值提供方，并补真实适配器；新应用字段同时登记全局恢复类别。工具、凭据和业务操作不因为出现在目录中就自动获得恢复能力。
3. 前端使用相同 ID。搜索与 MCP 的枚举自动跟随，不另加设置成员表。
4. 运行 `pnpm settings:docs` 更新参考页，`pnpm settings:docs:check` 检查生成结果，并补对应的字段、适配器及交互回归测试。

`settings_registry.test.ts` 检查 ID 唯一性、字段绑定、页面归属、默认值来源与全局恢复策略。桌面恢复测试逐页检查登记的全局字段都有真实适配器；搜索覆盖测试从实际控件读取标签或注册身份，避免目录与测试同时漏抄同一项。

## 功能目录与工具

[功能参考和工具索引](../guide/features.md)由 [feature_catalog](https://github.com/weq-devs/WeQ/tree/dev/packages/service/src/common/feature_catalog)、搜索和导航绑定、助手工具及 MCP 注册规则生成。设置定义继续由设置注册表提供。
标注已有教程时，在相应操作之前放置 `<a id="feature-稳定ID"></a>`，
然后在功能定义中引用此锚点。既有教程标题可以独立调整。

登记 `navigation: 'search'` 时同时绑定真实的搜索入口，点击后打开页面或选择器。
仅在特定会话、群或内容中出现的操作使用 `navigation: 'context'`，并登记所需对象。
新增工具应关联可以解释它的功能 ID，并沿用各调用面的注册规则。
更改目录、导航、关联工具或教程后，在 WeQ 主仓根目录运行 `pnpm features:docs`。
提交文档前可用 `pnpm features:docs:check` 核对工具关联、可链接的真实入口、教程锚点与生成结果。设置页继续用 `pnpm settings:docs` 更新。

`list_settings` 直接使用注册表的公开枚举，支持按 `page`、`query` 筛选，返回稳定 ID、路径、别名、恢复字段和作用域。不返回当前设置、凭据或账号内容，也不提供泛化配置写入。各项业务操作仍使用原有接口。
