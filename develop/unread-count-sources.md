# 未读计数：QQ 小表基准与共享快照

## 结果与来源

Desktop、Web、Remote 统一消费 `UnreadInfoService.getUnreadInfos()` 的结果。
普通私聊和群聊以 QQ 的未读小表及最近会话表为基准：

`可写私聊／群聊的有效阅读下限 = max(41002, 41032)`

`未读数 = max(0, 最新序号 - 有效阅读下限 - 区间内去重减计数项)`

减计数项来自 QQ 已维护的 `41024.40003`，只扣除 `下限 < seq <= 最新序号`。
最新预览为撤回或戳一戳时按会话和序号校验对应消息行。防撤回保留正文时，
通过撤回记录索引补充同一未读区间内的减项。两处补偿与 QQ 减项按序号去重。
最近会话表同时读取 `40020` 发送者；最新消息确认由当前账号发出时，将该序号并入减项，
避免跨端自发消息先更新最新序号、QQ 稍后补减项时短暂点亮未读。已观察的自发序号仅在内存
有界保留（最多 1024 个会话、每会话 64 项），QQ 减项接纳或阅读位置越过后释放，与 QQ 减项
去重，不抬高阅读位置、不清除已有未读；随后收到回复也不会重复计算这条自发消息。
发送者或自身 UID 缺失时不猜测方向，不为补偿读取消息历史。
群聊同时读取最近会话表的 `41220`。明确的群消息接收方式与未读数一起更新，群助手归类和
全局消息角标优先使用这份状态。字段缺失或群没有明确的最近会话状态时，沿用会话及群目录数据。
只改变接收方式也会发布该会话的差分，后台窗口可以据此更新角标。
`41027` 是手动未读标志，不是条数；实际数量为零时显示最小标记。
设备会话的 QQ 存储键为 `10_<设备 UID>` 和 `53_<设备 UID>`，分别对应会话类型 8 和 134。
取 QQ 和 WeQ 本地较新的阅读位置，从本地设备消息表统计此位置之后的入站条数。
查询以原消息时间和 ID 划定区间，同秒消息由 ID 区分。由对应手机或平板发送的正文才参与计数，
电脑自发、系统提示均排除。未读数字由 WeQ 本地查询提供。

QQ 内存读取适配器保留为显式 `compareQqCounts()` 诊断，不自动定位、轮询或接管显示。
适配器按 native 的只读能力、覆盖范围与布局声明启用，覆盖 macOS ARM／Intel、Windows x64
及 Linux x64／arm64。native 每次读取核验实际加载模块、QQ 进程与账号持库关系，旧 native
缺接口或没有可用布局时跳过。换 PID 清理旧定位，冷定位不阻塞数据库角标。
数据库已被 WeQ 标为已读、QQ 内存仍保留角标时，WeQ 按数据库显示，不来回切换来源。
此规则不表示 QQ 本体界面会因外部 SQL 立即更新。

## 启动与更新

账号初始化通过 `getAllUnreadInfos()` 一次读取两张小表，包含缺最近会话行的未读记录。
请求消费服务端共享快照；不同前端、不同请求批次共享初始化与刷新任务。
旧 `watermarksOnly` 参数仍可传入，但不再切换读取模式；生产结果不再使用 `countPending`。

前端首次并行获取传输批次，合并为一次状态提交，不等待聊天首屏或 QQ 内存定位，
不再逐会话精算。账号来源不变时 HMR／刷新器重建保留已显示角标和进行中的阅读保护。
Web／Remote 按 SuperJSON 序列化及 URL 编码后的实际长度拆分未读请求，遵守 HTTP
批次的 2048 字符上限；桌面 IPC 仍按最多 256 个会话分批。实时变化独立读取，不等待
首次全量快照完成；首次失败仍可展示后续成功的实时结果，迟到快照不覆盖较新的变化。

服务端复用文件变化通知，50ms 合并后重读小表，比较每个会话的字段并只通知变化目标。
有订阅者时共享每 1.5 秒补查，覆盖纯阅读变化；最后一个订阅者退出后停止定时补查。
新消息通知只请求小表刷新，不另行累加消息数。读取失败或单行损坏保留已有成功快照，
后续刷新自动修正，不用零覆盖，也不转入历史扫描。

## 操作与迁移

已读写入捕获时的固定位置，并清理范围内提醒及手动未读标志；重试不追随新消息。
启用「保留尚未读到的消息的未读计数」时，普通私聊和群聊在前台向下阅读，
提交实际看见且从视口上沿滑出的消息序号。实时会话触底时，也提交当前可见的有效序号。
宿主从小表当前阅读水位开始，只推进连续可确认的区间。小表确认的减项或撤回可跨过，
未确认的缺口保留。写库与已读上报使用同一个目标序号。
手动未读只置标志，不降低阅读水位。撤销恢复本次操作字段，并合并后来新增的提醒。
同会话写入串行执行，后续操作取代旧的待执行／重试操作。

可写私聊和群聊不再读取或保存 WeQ 的本地操作覆盖。成功写入后仅回读受影响会话，
按实际数据库状态展示；自动已读写入失败时按固定位置重试，手动批量标记报告未保存的会话，
仅为成功项保留撤销记录。撤销回读 QQ 数据库，不从旧快照拼接提醒。

只读目录仍使用 `unread.json`，有效阅读下限同时考虑尚有效的本地操作。
设备会话也在 `unread.json` 保存手动标记及当前电脑的阅读位置，QQ 的位置追上后移除本地覆盖。
QQ 在线会话可用时，自动阅读和手动标为已读均会上报。设备上报以本人 UID 和原消息时间发送，
省略序号字段。运行中的 QQ 界面如何接收设备已读仍待验证。
该文件不保存未读数、实时未读序号集合、历史基线或观察水位。旧的普通会话记录不再覆盖可写 QQ 库。
