# 维护与诊断工具

密钥扫描与其他设备密钥位于 **设置 → QQ → 凭据管理**，其后是独立的 **QQ 登录管理** 页。数据库修复位于 **QQ → QQ 数据库管理 → 数据库检查与修复**。QQNT 抓包、通话抓包、签名器状态和逆向解析位于 **QQ → QQ 高级工具**。登录记录和逆向解析直接显示在设置正文，数据库修复与 QQNT 抓包使用独立系统窗口。日志与性能的记录设置及独立监视窗口入口位于 **关于 → 日志与性能**，详见[性能监视](performance-monitor.md)。

## 什么时候会用到这些

这几个入口藏得比较深，但真出事时最有用：

| 你遇到的情况 | 用哪个 | 在哪 |
| --- | --- | --- |
| 启动页没有我的号 / 显示不出账号 | 密钥扫描 | 设置 → QQ → 凭据管理 |
| 手上是别人（或旧手机）导出的 `nt_msg.db` | 其它设备密钥 | 同上 |
| 提示数据库损坏、消息读不出来 | 数据库修复 | QQ → QQ 数据库管理 → 数据库检查与修复 |
| 想看 QQ 到底发了什么、或某个功能不灵 | QQNT 抓包 + Protobuf 解析 | QQ → QQ 高级工具 |
| 换机器后要处置旧设备身份 / 被风控 | 设备 guid（查看 / 随机更换） | QQ → QQ 登录管理 |

只想先算个 hash 或密钥、不在本机操作时，用文档站的[工具箱](/tools/)。

本页介绍以下工具，其余维护入口见[设置总览](settings.md)：

| 工具 | 说明 |
| --- | --- |
| **密钥扫描** | 零注入内存扫描主密钥 |
| **其它设备密钥** | 获取账号其它设备的密钥 |
| **数据库修复** | 备份 · 重建坏库 · 可回滚 |
| **QQNT 抓包** | 非侵入式读网卡 · TCP 重组 · d2key 解密 |
| **Protobuf / JCE 逆向** | hex/base64 → 简洁 JSON |
| **QQ 登录账号管理** | 快速登录账号 · 删除账号 · 更换设备标识（GUID） |

「QQ → QQ 数据库管理 → 数据库检查与修复」的修复入口、数据库损坏提示及导出任务中的「尝试修复」打开同一修复工具。从导出任务进入时携带具体数据源，同号在线账号与导入备份分别解析。

日常读取遇到疑似损坏时，WeQ 会在后台复查报错的数据库。检查未完成或部分结构未核验会留在检查报告里；确认损坏时显示全局提醒，并可从提醒进入检查详情。同一数据源的对应数据库完整通过深度体检后，旧横幅会收起。聊天记录或搜索来源实际读取失败时，相关页面会显示受影响的范围。

## 1. 密钥扫描

后端遍历 `login.db` 的全部历史账号，逐个反查 `nt_msg.db` 目录与在线 QQ 进程 pid（Windows 走
Restart Manager、Linux 走 fcntl 写锁）。

- 在线账号卡片亮起（绿色在线点 + 高亮），离线账号置灰；
- 卡片显示头像、昵称 / QQ 号、在线 / 离线；工具栏有「刷新」，并显示「N / 总数 在线」；
- 点击任意卡片 → 卡片加载动画 → 对该账号进程做**零注入内存扫描**
  （`nt_helper scanKeyFromDatabaseWithProgress`）：先扫 HMAC_SHA1 锚点 / 簇，找不到
  可验证的密钥时自动**回退扫描整个内存**（较慢）；扫描期间结果弹窗显示两阶段进度条；
- unix（Linux / macOS）上读别的进程内存通常要管理员权限：普通用户直接扫不到时，会像
  「读取 QQ 内存 / 抓包」一样弹**管理员密码框**，授权后由一个临时的 root 子进程重扫
  （macOS 在 SIP 开启时先尝试直接读取及长期助手，可使用 [QQ 调试副本](macos-debug-copy.md)，失败后不发起无效的 sudo 授权）；
- 扫描结果弹窗显示：头像 / 昵称 / QQ 号 / PID，以及
  - 恢复出的**密钥**（可一键复制）；
  - 密钥所在内存的**上下文 hexdump**（前 256B + 后 256B，**高亮**密钥字节）；
  - 或失败原因。

## 2. 其它设备密钥

用来处理「我手上这份 `nt_msg.db` 是别的设备导出的」这种情况。

- 先检查是否有可用的在线 QQ 实例（复用密钥扫描的 pid 判定）；没有就把「获取密钥」按钮置灰；
- 选择其它设备导出的 `nt_msg.db` → 读取头部字节（256B）显示 hexdump，**高亮**发包用的
  `key_meta`（文件偏移 `0x2f..0xaf`，与 native 的 `request_decrypt_key` 一致）；
- `key_meta` 下方给出有效 / 无效徽章；
- 点「获取密钥」→ 显示加载动画 → 按 bootstrap 的实例取密钥流程（跳过注入，直接调
  `nt_helper requestDecryptKey`）→ 返回密钥或失败原因；
- 成功后显示密钥（可复制）与返回它的在线实例 PID。

::: info

这里用到的「在线实例」要求**当前来源已启用 QQ 在线能力，且凭据与在线会话已就绪**。请先打开[「启用 QQ 在线能力」](settings.md#qq-在线能力与启用方式)，并等待当前来源就绪。密钥扫描是零注入的，不依赖该在线请求能力，仍需满足平台内存权限。

:::

## 3. 数据库修复

维护窗口分为「开始体检」「体检进度与结果」「开始修复」「修复进度与结果」。后三个页签在没有内容时置灰，切换标签页时任务继续执行。账号、维护状态和历史报告入口始终在顶栏。

### 主动体检与持锁等待

- 打开窗口、从异常通知跳转或查看历史结果，都不会自动体检。在「开始体检」下方切换体检类型。快速体检取得修复所需的页信息，深度体检额外执行完整结构检查。
- 从「开始体检」页底部勾选待检查的数据库，也可以全选或取消全选。列表隐藏已完成或已排队做同级或更深体检的库。切换到深度体检时，已排队做快速体检的库也能选中升级。点击圆形按钮后，窗口立即进入「体检进度与结果」。追加或补充检查沿用本轮已完成的检查和维护锁。
- 一批数据库可以并行体检。通过右上角「数据库修复设置」调整「体检并行数量」，默认同时检查 2 个，可设为 1–8 个。更改会在下次开始或继续体检时生效。多库检查时，点击数据库卡片查看该库的进度。
- 建议先退出 QQ。WeQ 保留聊天、资料等只读浏览；写库及相关 QQ 修改操作会明确提示维护中，后台自动写库任务暂停。实际替换前仍会检查外部占用，避免 QQ 等程序继续持有被替换的旧文件。
- 报告列出本轮所选的库，包括体检失败和未完成的库。坏页归属不明时，可以补查坏页归属和数据库结构，复用已完成的页签名检查。如果快速体检已经核验了部分正常页，也可以直接查看深度修复方案。快速修复需要足够的坏页定位证据。
- 选库卡片和数据库检查详情在文件名下显示已知用途。
- 「暂停体检」会保留已取得的维护锁和已完成的检查。继续时复用已完成的结果，同一轮维护内的页签名检查从最近保存的检查点继续。未完成的数据库结构检查会重新执行。也可以返回「开始体检」页切换续检类型或追加数据库。已有完整页检查结果时，可导出部分报告。有可用方案时，「前往修复」会打开修复页。
- 数据库卡片显示「等待快速体检」或「等待深度体检」。将同一个库的待检类型切换为深度体检时，只保留深度体检。已完成快速体检的库会在同一张卡片上显示已有结果。本轮维护锁仍有效时，WeQ 会复用已完成的页签名检查。
- 维护期间，顶栏统一显示可点击的「维护中」。体检、备份和重建期间，点击后可以确认停止当前操作并解锁。历史报告会保留，下次修复需要重新体检。

### 修复

- 在「体检进度与结果」的结论卡选「进入修复」。体检未发现需要修复的问题时，悬停按钮可查看原因。「开始修复」页根据所选数据库预选修复方式。所选库都符合快速修复条件，或都能在开修时核验这些条件，就预选快速修复。若有库只能深度修复，就预选深度修复。手动切到快速修复时，无法快速修复的库会置灰并说明原因。圆形「开始修复」按钮显示本批空间预算与警告。
- **快速修复**可以从快速体检直接开始。WeQ 复用本轮扫出的坏页页号，核验空闲叶页和可访问的历史备份。如果还剩一页无法恢复，会限时尝试找出能通过原页签名的单字节修正。每个坏页都有修复依据后，WeQ 才测试原库所在卷的克隆能力，在同卷工作副本上修复，完整复核通过后换回。复核可能通读数据库。「修复前备份」设为「开启」时还会额外留一份克隆备份，已有历史备份会自动参与核验。
- **深度修复**抢救可读记录并重建。损坏的记录可能无法恢复。新原生组件可以按需解密源页并直接写出加密库。工作区可放在不同卷，最终产物始终写在原库卷。
- 修复遇到空间不足时，可在「修复进度与结果」选择「继续修复」，重新检查空间后重试。快速修复未通过复核，且确认锁仍有效、原库未变时，可先查看深度修复方案，再决定是否启动。WeQ 复用本轮已完成的页检查与已校验的备份，并跳过已经修好的库。维护锁失效、发现源库改动或提交结果不明确时，先重新核对原库。
- 确认开始修复后，窗口进入「修复进度与结果」。该页只列本次选中修复的库，可以看进度、停止修复和导出结果。点击「停止修复」后，可在弹窗中选择继续或确认停止。确认后会中断尚未提交的重建，并跳过后续数据库。已修复成功的库和本轮报告会保留。本轮处理结束后自动结束账号维护、统一解锁。
- 替换及最终复核期间，点击「维护中」会询问是否撤销当前库的替换并停止维护。确认后取消尚未完成的替换，或者恢复已换下的原库并核对指纹，成功后解锁。即使关闭「修复前备份」，本次替换期间也会临时保留原库。此前已修复成功的其他库保留结果。
- 快速和深度修复都在替换前检查产物的页签名与结构。换入后试读正式路径上的数据库，失败时尝试恢复原库并记录结果。恢复失败时可以从「维护中」重试。留有修复前备份时，记录修复后指纹用于以后恢复。恢复历史备份时先验证备份，再替换数据库。当前库有变化或仍有未合并日志时，会明确提示覆盖这些数据。替换失败时不会丢弃原日志。

### 窗口、报告与进度

- 体检准备时显示当前处理的数据库、日志合并或加锁状态，以及已处理的库数。深度体检定位坏页时显示遍历页数和已定位的坏页数。记录与索引检查按表归并，当前表自动展开，已完成的表可按需展开。
- 深度修复显示已处理的表数、当前表名及累计字段数。随后显示标记已归属页、扫描原库、核查未归属页和保存找回记录的计数。重建索引时显示索引名和已处理的索引数，提交后继续检查修复产物。使用临时明文副本重新加密时，显示已写入的字节数。
- 快速修复核验条件时显示空闲页和历史备份的处理数量。需要尝试单字节修正时，显示当前步骤。
- 快速修复写入已核验的页，以及严格深度修复为明文副本清零坏页时，按实际写入页数显示进度。产物结构检查显示当前步骤及其进度，最近完成的表与索引检查集中折叠，可按需展开。记录修复后指纹和撤销替换后的原库校验按读取字节数显示进度。从历史报告恢复备份时，可在窗口查看备份复制与校验的进度。
- 体检完成、等待决定时关闭窗口，会询问继续维护还是放弃并关闭。修复开始后，关窗只关闭界面，任务在后台继续；修复中退出 WeQ 会询问是否停止修复，不要求做完整个批次。
- 重新打开窗口时会接续仍在进行的维护。主动结束体检维护后返回开始体检页，主动结束修复维护后可留在结果页。已结束的维护可从历史报告查看。
- 运行时可以用「追加体检」选库，再点「加入本轮体检」。可以切换快速或深度体检，追加的检查在当前批次之后开始。若没有可追加快速体检的库，打开追加页时默认选中深度体检，两个选项均可手动切换。快速体检中的库也可以排队做深度体检，WeQ 会复用已完成的页检查。如果选库期间当前批次已完成，勾选会保留，可直接在同一页确认追加。尚未开始的库会随暂停保留，继续体检时一并检查。体检完成后的报告结论卡也可追加体检，若上一轮是快速体检且仍有待快速体检的库，打开快速体检选库，否则打开深度体检选库。点「导出报告」可从菜单选择 HTML、Markdown 或 JSON。
- 历史报告从右上角入口打开独立浮层，列表、报告详情和恢复入口不占用维护页；本地保留的报告不因关窗、重启或新检查覆盖，支持 HTML、Markdown、JSON 导出和确认删除。仍在更新的报告不能删除；删除维护报告不更改当前数据库或修复备份，旧修复记录若连同备份删除会单独说明。报告区分执行状态和诊断结论：成功检查发现异常仍是执行完成，未完成的检查与已确认的损坏分别说明。
- 报告逐项区分「WeQ 支持修复」「WeQ 不支持修复」及证据不足时的「可能支持修复」。没有页 HMAC 不代表数据库完好；明文库不受当前加密库重建工具支持，也不因此视为损坏。
- HTML／Markdown 导出直接包含已有修复记录中的前后体积、源库坏页与全零页、各阶段耗时及产物自检结果；未取得的结果显示未知或未核验。普通进度最多每 2 秒保存一次完整报告，单库完成、失败及停止等关键状态立即保存，界面进度仍实时更新。
- QQ 专用 FTS 分词器在独立检查环境中不可用时，报告列出未核验的结构并显示部分完成，不把普通表通过当成整库全部正常；修复产物的复核也保留相同说明。
- 快速体检、深度体检、修复及工具内的备份、恢复不创建任务列表条目，进度和结果在修复窗口内查看；关窗后修复仍在后台继续。
- 工具任务的横幅只在对应账号及数据源的主窗口显示。修复窗口获得焦点时会收起横幅，聚焦期间的完成结果也不补发。手动关闭修复进度横幅后，进度更新期间会保持隐藏。再次切到修复窗口并离开时，仍在进行的修复会重新显示进度。点击体检完成横幅可直达「体检进度与结果」，查看本轮结论和各库详情。新检查须主动启动。正常体检进度与正常完成保持静默。
- 磁盘已满等原因导致报告暂时不能写入时，当前结果保留在内存并在页内提示，空间恢复后补存；未补存前不要退出应用。
- 数据库列表单行横向滚动，下面共用可折叠阶段时间线；最下方的检查结论、指标和问题明细单独放入「数据库检查详情」卡片，保持一致的内边距与对齐。当前阶段默认展开，显示真实处理数量及对象，点击阶段标题可收起或展开。已完成的阶段可以回看，需关注的步骤默认展开。只有具体步骤有可靠分母时才显示百分比，账号只显示完成库数，不拼凑整体比例；总耗时仅显示一次，页签名检查和文件读写在有可靠数据时显示当前速度。

### 空间与工作区位置 {#空间与缓存位置}

- 圆形「开始修复」按钮汇总已选数据库的空间预算。深度修复按卷、按阶段估算新增空间，计入未合并 WAL 可能带来的主库增长；建议预留在此基础上加 25% 与每卷 64 MiB 缓冲。快速修复的坏页条件需要先核验时，开始后再计算空间。
- 「开始修复」页自动更新可用空间。空间不足或偏低时，圆形按钮内显示警告与可用空间。如果工作区所在磁盘空间紧张，可点击「更改工作区位置」移到空间更大的磁盘。可用空间低于建议值但仍够写入时，点击「开始修复」，在弹窗中选择「仍尝试修复」。每个库开始时都会重新核算。修复中空间不足时保留本轮体检结果和维护锁，可在「修复进度与结果」处理后继续。
- 修复中持续检查剩余空间与本次临时文件实际占用，并按当前阶段计算后续写入、删除的峰值；已写完的文件不重复预留，后续释放只抵扣所在卷的预算，不用整轮总预估量与当前剩余空间比较。途中出现风险同样显示警告；不足以继续写入时中断未提交重建、清理本次临时件，保留锁和体检结果以供处理后重试。
- 同一次持续维护中，提交前失败后的空间预检不再计入已成功备份的大小；备份仍占用磁盘，但当前可用空间已经反映这部分占用，重试只预留后续新增空间。更换工作区位置也会沿用原位置的成功备份。维护结束后不再复用；备份缺失、大小变化或内容校验失败时恢复完整备份预算，重新备份后再重建。
- 「数据库修复设置」里的「修复前备份」可选择「关闭」「仅深度修复」或「开启」。默认只在深度修复时备份。「开启」也为快速修复保留备份，选择「关闭」需要确认。
- 右上角设置按钮打开独立浮层，在「备份与修复工作区位置」更改备份和临时工作文件的位置，或恢复默认，维护页不再常驻显示路径。体检、持锁等待期间也能调整，不需要放弃体检结果；修复正在使用工作区时禁用更改。历史索引与报告保持原位，已有备份不会被自动迁移，仍可从原记录回滚。自定义目录失效时停止新修复，不创建替代目录。
- 快速修复按原库卷预算空间。深度修复在支持流式重建时使用对应的预算，旧组件仍按包含明文中间件的方式预检。
- 深度修复备份优先尝试文件系统克隆，克隆不可用时正常复制，预检按普通复制预算。成功与失败的修复记录均按默认最近 3 份独立备份文件保留，多次重试共用的文件只算一份，历史记录和报告保留。删除单条旧记录不删除其他记录仍引用的备份。若最后一条引用的备份清理失败，保留记录供重试。主动清除共用备份时同步更新全部关联记录。
- 当前自定义位置下的修复数据也会计入存储管理，清除时需确认失去回滚能力并退出应用，不参与普通缓存清理。

### 布局迁移（旧版误修复的大库）

旧版 WeQ 在 1 GiB 以上的 QQ 库上可能把它误判成损坏，并用 standard SQLite 的页布局
「修复」出一个错位库：第 `262144` 页是真实数据，而 QQ 认为它是保留页。新版本不会在启动
时自动检查；**主动开始体检**时才会读两个 4 KiB 页做判断：

- 文件不超过 1 GiB：不检查，直接按普通修复处理；
- 第 `262144` 页有数据、第 `262145` 页全零：判定为旧版误修复的 standard 布局，体检结果记录此问题，修复时按 standard 源布局读取；
- 第 `262144` 页全零、第 `262145` 页有数据：QQ 布局，正常；
- 其它组合：不提示迁移。

布局迁移与普通修复共用同一条流程（备份 → 重建 → 替换 → 自检），区别是
按 standard 页号读出全部数据、再写回 QQ 布局。它复用本次体检结果和维护锁。失败时请以报告中的实际阶段与备份状态为准，旧版 native 不支持时会在替换前中止。

::: warning

修复目标在渲染层只用**库名**标识，目录、密钥、算法都在主进程解析 —— 这样接口不会变成任意
路径写入器。

:::

## 4. QQNT 抓包

非侵入式读网卡（**不注入、不改 QQ**）：TCP 重组 → MSF 帧切分 → 用该会话的 d2key 做 TEA 解密。
版式参考 reqable：左侧会话表（同一 `seq` 的发包 / 收包合成一行），右侧出该方向的
总览 / 解密数据 / 原始数据。

从 QQ 高级工具打开独立系统窗口，不替换设置页或侧栏；重复打开会聚焦原窗口并保留已捕获的数据。关闭抓包窗口或切换 WeQ 账号、数据源会释放该窗口持有的抓包会话；启动尚未返回时，迟到句柄会在返回后释放，不误停后来建立的会话。锁屏会隐藏窗口内容、暂停帧读取，已经开始的底层抓包仍保留，解锁后继续读取。

宽窗口左右分栏，窄窗口上下分栏；分隔条可拖动，也可聚焦后用方向键调整。账号选择、方向与关键字过滤、请求/响应明细、复制及 JSON/JSONL 导出保留在同一窗口。请在关闭前导出需要保留的帧；关闭窗口不保留未导出的临时列表。

- 账号列表在打开窗口及返回前台时自动读取，读取失败可就地重试。选一个**在线账号** →「开始抓包」→ 可选暂停 / 继续 / 停止 / 清空；
- 过滤条可按方向（全部 / 发包 / 收包）+ 关键字（命令字 / seq）筛；
- 解密数据栏对正文自动按 protobuf → JCE → 去长度前缀的顺序解析成 `{tag: value}` 树；
- Windows 需先装 [Npcap](https://npcap.com/)；Linux/macOS 需要 root，会弹授权窗口把抓包
  会话放进临时提权子进程（WeQ 本体不以 root 运行）。
- macOS 自动端口模式要求带 PKTAP 进程归属的权限助手。旧助手会提示在设置中修复长期授权，避免混入同机其他 QQ 的连接；固定端口仍可用于单连接诊断，但不能据此宣称覆盖了所有连接。

### 导出

工具条的**「导出」**按钮把当前列表里**符合过滤条件**的帧（也就是眼前看到的这些）导出成文件，
下拉里选格式：

| 格式 | 内容 |
| --- | --- |
| **JSON** | 一份自包含文档 `{ meta, frames }`，每帧带 `decoded` 解析树与 raw / plain / body 的 hex |
| **JSONL** | 每行一帧，方便 `jq` / `grep` 流式处理 |

桌面端弹系统保存框、落到所选路径；Web 端写进服务端导出目录，当前窗口仍活动时触发浏览器下载。窗口关闭、切源或锁屏后才返回的结果不在旧文档触发下载，也不把旧路径回填到新来源。
导出结果会以一条提示（含帧数 / 体积 / 路径）反馈。

## 5. Protobuf / JCE 逆向

把 hex / base64 输入，按 **protobuf** 或 **JCE**（QQHook TarsParser 语义）解析为 `{tag: value}`
的简洁 JSON（对齐 CyberChef 的 Protobuf Decode）。**嵌套 message 会自动逐层展开**，不用再手动把
子字段的 hex 拿出来二次解析；`tag ≥ 1001` 的字段名直接跟在字段号后面显示。

顶部可切换两种视图：

- **简洁**（默认）：纯 JSON，只有字段号与值 —— 能当可读文本的 bytes 直接给字符串，其余给 `0x…` hex。
- **详细**：每个值旁再出现转换按钮，用于逐个值做旁路解读：

| 类型 | 可转换 |
| --- | --- |
| bytes | hex ↔ 文本 / Base64 / 按 protobuf 解析 / 按 JCE 解析（支持混合嵌套） |
| 整数 | 有符号 ↔ 无符号 / bool / 时间戳 / zigzag / hex |
| fixed64 / fixed32 | 整数 ↔ float |
| 字符串 | 文本 ↔ hex |

面板支持自动识别格式、复制结果、清空、载入示例。适合研究 QQ 协议里那些二进制字段。

::: info

MCP 的 `decode_blob` / `decode_db_blob` 也是同一套输出：纯 JSON `fields` 树（嵌套自动展开）
外加一个 `names` 图例，把树里出现过的 `tag ≥ 1001` 字段名单独列出来，避免字段名把数据树撑长。

:::

::: tip

**开头的长度前缀会自动识别并剥离**。抓包 / 内存里经常拿到形如 `00 00 00 D5 0A 08 …` 的字节：
前几字节是长度头，直接解析会让游标跑偏。解析器会枚举 4 / 2 / 1 字节 × 大端 / 小端，
只有「读出的值 = 整包或负载长度」**且**剥完能完整解析时才采用，所以不会硬编码「砍 4 字节」，
正常数据也不会被误削；命中时结果里会标出剥掉了什么。

:::

## 6. QQ 登录账号管理

管理**本机 QQ 的登录记录和设备标识**，数据来自 `login.db` 及设备标识文件。修改前需要退出所有 QQ 实例，重新启动 QQ 后核对结果；不需要重启 WeQ。

### 页面内容

- 顶部的「本机设备标识（GUID）」卡片提供复制和「随机更换」。
- 下方的「登录账号列表」卡片逐行列出账号，显示头像、昵称、QQ 号、「快速登录」标记（该号在 `login.db` 里有缓存的
  a1）、上次登录时间，以及**数据目录还在不在**（只有登录记录、目录已经被删的号会标出来）。

### 三个动作

| 动作 | 做了什么 | 影响 |
| --- | --- | --- |
| **移除快登** | 清掉 `login.db` 里缓存的 a1（`[1004]`） | 账号行还在，但下次 QQ 启动它不再出现在快速登录列表，要重新输密码 / 扫码 |
| **删除账号** | 从 `login.db` 删除该账号的登录记录 | **不会删除聊天记录与账号目录**；不等于注销 QQ 账号，后续仍可重新登录 |
| **随机更换 guid** | 随机生成设备 GUID 并写回本机设备标识文件 | 改变后续请求使用的设备标识，可能影响设备识别或触发登录验证，请在重新启动 QQ 后核对 |

### 必须「所有 QQ 都退出」才能改

三个写操作都受同一条闸门约束：**检测到有 QQ 实例在运行就全部置灰**，页面上会写明原因。

因为 `login.db` 与设备标识文件（Linux `global/nt_data/msf/machine-info`、macOS
`machineid-info`、Windows `<msf>\Registry20`）都是 QQ 常驻读写并缓存在内存里的 —— 在线时改完
会被它覆盖回去（Windows 的硬件回退甚至会自动重写自己的缓存）。与其做一个静默失效的按钮，
不如要求先退出 QQ。实例数用 QQ 自己记的 `launcherCounts` 判断，不数进程。

::: info

换完 guid，WeQ 自己存的那份账号配置会一起同步（guid 与按旧 guid 解出来的 a1 payload 缓存），
所以之后从 WeQ 发起的快速登录 / 抓包 / 在线识别不会拿旧 guid 去冒充新设备。

:::

## 7. QQ 在线能力开关与受限状态

「启用 QQ 在线能力」位于[设置 → 能力 → QQ 在线能力](settings.md#qq-在线能力与启用方式)。关闭后立即停用依赖 QQ 会话的在线功能。受限详情里的启用按钮可重新打开同一个设置。关闭时的影响如下。

- 依赖在线实例的功能（其它设备的密钥、需要发包补齐的导出等）会明确提示不可用；
- 本地记录查看、本地文件导出、密钥扫描等不依赖在线 QQ 的功能仍可使用；涉及缺失媒体或在线记录的内容可能无法补全。

克隆、助手及其他 API 功能按各自的网络设置访问服务商。
