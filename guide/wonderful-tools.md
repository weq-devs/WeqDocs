# 维护与诊断工具

密钥扫描与其他设备密钥位于 **设置 → 凭据与数据 → 凭据管理**，数据库修复位于 **凭据与数据 → QQ 数据库管理 → 数据库检查与修复**；抓包、签名器状态、逆向解析和登录记录与设备标识统一位于 **凭据与数据 → QQ 高级工具**。登录记录和逆向解析直接显示在设置正文，数据库修复与 QQNT 抓包使用独立系统窗口。日志与性能的记录设置及独立监视窗口入口位于 **关于 WeQ → 日志与性能**，详见[性能监视](performance-monitor.md)。

## 什么时候会用到这些

这几个入口藏得比较深，但真出事时最有用：

| 你遇到的情况 | 用哪个 | 在哪 |
| --- | --- | --- |
| 启动页没有我的号 / 显示不出账号 | 密钥扫描 | 设置 → 凭据与数据 → 凭据管理 |
| 手上是别人（或旧手机）导出的 `nt_msg.db` | 其它设备密钥 | 同上 |
| 提示数据库损坏、消息读不出来 | 数据库修复 | 凭据与数据 → QQ 数据库管理 → 数据库检查与修复 |
| 想看 QQ 到底发了什么、或某个功能不灵 | QQNT 抓包 + Protobuf 解析 | 凭据与数据 → QQ 高级工具 |
| 换机器后要处置旧设备身份 / 被风控 | 设备 guid（查看 / 随机更换） | 凭据与数据 → QQ 高级工具 → 登录记录与设备标识 |

只想先算个 hash 或密钥、不在本机操作时，用文档站的[工具箱](/tools/)。

本页介绍以下工具，其余维护入口见[设置总览](settings.md)：

| 工具 | 说明 |
| --- | --- |
| **密钥扫描** | 零注入内存扫描主密钥 |
| **其它设备密钥** | 获取账号其它设备的密钥 |
| **数据库修复** | 备份 · 重建坏库 · 可回滚 |
| **QQNT 抓包** | 非侵入式读网卡 · TCP 重组 · d2key 解密 |
| **Protobuf / JCE 逆向** | hex/base64 → 简洁 JSON |
| **QQ 登录账号管理** | 快速登录账号 · 删除账号 · 更换设备标识（GUID） |

「凭据与数据 → QQ 数据库管理 → 数据库检查与修复」的修复入口、数据库损坏提示及导出任务中的「尝试修复」打开同一修复工具。从导出任务进入时携带具体数据源，同号在线账号与导入备份分别解析。

## 1. 密钥扫描

后端遍历 `login.db` 的全部历史账号，逐个反查 `nt_msg.db` 目录与在线 QQ 进程 pid（Windows 走
Restart Manager、Linux 走 fcntl 写锁）。

- 在线账号卡片亮起（绿色在线点 + 高亮），离线账号置灰；
- 卡片显示头像、昵称 / QQ 号、在线 / 离线；工具栏有「刷新」，并显示「N / 总数 在线」；
- 点击任意卡片 → 卡片加载动画 → 对该账号进程做**零注入内存扫描**
  （`nt_helper scanKeyFromDatabaseWithProgress`）：先扫 HMAC_SHA1 锚点 / 簇，找不到
  可验证的密钥时自动**回退扫描整个内存**（较慢）；扫描期间结果弹窗显示两阶段进度条；
- unix（Linux / macOS）上读别的进程内存通常要管理员权限：普通用户直接扫不到时，会像
  「读取 QQ 内存 / 抓包」一样弹**管理员密码框**，授权后由一个临时的 root 子进程重扫
  （macOS 在 SIP 开启时先尝试直接读取及长期助手，可使用 [QQ 调试副本](macos-debug-copy.md)，失败后不发起无效的 sudo 授权）；
- 扫描结果弹窗显示：头像 / 昵称 / QQ 号 / PID，以及
  - 恢复出的**密钥**（可一键复制）；
  - 密钥所在内存的**上下文 hexdump**（前 256B + 后 256B，**高亮**密钥字节）；
  - 或失败原因。

## 2. 其它设备密钥

用来处理「我手上这份 `nt_msg.db` 是别的设备导出的」这种情况。

- 先检查是否有可用的在线 QQ 实例（复用密钥扫描的 pid 判定）；没有就把「获取密钥」按钮置灰；
- 选择其它设备导出的 `nt_msg.db` → 读取头部字节（256B）显示 hexdump，**高亮**发包用的
  `key_meta`（文件偏移 `0x2f..0xaf`，与 native 的 `request_decrypt_key` 一致）；
- `key_meta` 下方给出有效 / 无效徽章；
- 点「获取密钥」→ 显示加载动画 → 按 bootstrap 的实例取密钥流程（跳过注入，直接调
  `nt_helper requestDecryptKey`）→ 返回密钥或失败原因；
- 成功后显示密钥（可复制）与返回它的在线实例 PID。

::: info

这里用到的「在线实例」要求**当前来源已启用 QQ 在线能力，且凭据与在线会话已就绪**。关闭[自动启用偏好](settings.md#账号安全与凭据)后仍可手动启用本来源；未启用或能力未就绪时不能向 QQ 请求密钥。密钥扫描是零注入的，不依赖该在线请求能力，仍需满足平台内存权限。

:::

## 3. 数据库修复

数据库修复按整个账号及本次数据源维护。选择快速或深度体检后主动开始扫描，取得结果后再修复；修复只能重建仍可读取的内容，无法保证恢复全部数据。

### 主动扫描与持锁等待

- 打开窗口、从异常通知跳转或查看历史结果，都不会自动扫描。「开始扫描」左侧的分段选择提供「快速体检／深度体检」：快速体检取得修复所需的页信息，深度体检额外执行完整结构检查。
- 开始后先锁定此账号、本次数据源的全部目标数据库，再扫描，不为扫描另做整库快照。扫描完成后继续持锁，结果可以直接用于修复。
- 建议先退出 QQ。WeQ 保留聊天、资料等只读浏览；写库及相关 QQ 修改操作会明确提示维护中，后台自动写库任务暂停。实际替换前仍会检查外部占用，避免 QQ 等程序继续持有被替换的旧文件。
- 单个库扫描失败时保留部分完成报告，其他已有完整常规扫描结果的库仍可修复。
- 扫描运行时不能切换模式；点击「暂停扫描」，待当前检查退出后可切换模式并继续。只要已有完整页扫描结果，就保留维护锁和已完成检查，可继续扫描、修复就绪库，或主动结束维护；继续深度体检不会重做已完成的结构检查。没有任何数据库完成扫描就停止时，自动释放维护锁，不保存报告。
- 快速体检后，只要仍持有维护锁且有已完成页扫描的库需要深度检查，切换到「深度体检」并点击「继续扫描」，即可复用已完成的页扫描，补齐其余检查。
- 点击「重新扫描」并确认后，结束旧一轮维护并重新检查全部目标数据库，历史报告保留；取消则继续查看现有结果。
- 等待决定时不再转圈或累计执行耗时，页面明确显示数据库仍在维护中。选择「结束维护」可放弃本次结果并统一解锁，历史报告保留。

### 修复

- 只有本次维护中已完整扫描、且支持重建的数据库才能勾选。默认勾选支持修复的异常库，其他已扫描的可修复库也能手选；不能跳过扫描独立修复。
- 点击数据库卡片只切换查看该库的检查详情与执行过程，不改变修复对象；勾选或取消请使用卡片右上角的复选框。
- 修复直接使用扫描结果，执行备份、临时重建、产物检查、替换与最终复核，不再扫描源库。空间不足、工作区不可写或被其他程序占用等提交前问题，只要维护锁仍有效且未替换原库，就返回「查看结果」并保留扫描结果；处理后可直接重试，已成功的库不重复修复。本次维护中已经成功的备份会校验后复用，不再复制一份；失败时清理的临时重建文件仍需重新生成，不支持从文件中途续写。已进入替换或源库状态不能确认的失败单独记录，不能把旧扫描当作可重试结果。
- 「停止修复」会中断尚未提交的临时重建，不再启动后续数据库；已经成功的库不回退，停止也留下报告。本轮处理结束后自动结束账号维护、统一解锁。
- 原生重建报告已确认产物自检失败时，在替换前中止并保留原库；替换后的最终复核仍照常执行，复核失败且有备份时尝试还原，实际结果写入报告。恢复历史备份时先验证备份，再替换数据库；当前库有变化或仍有未合并日志时，会明确提示覆盖这些数据。替换失败时不会丢弃原日志。

### 窗口、报告与进度

- 扫描完成、等待决定时关闭窗口，会询问继续维护还是放弃并关闭。修复开始后，关窗只关闭界面，任务在后台继续；修复中退出 WeQ 会询问是否停止修复，不要求做完整个批次。
- 历史报告从右上角入口打开独立浮层，列表、报告详情和恢复入口不占用维护页；本地保留的报告不因关窗、重启或新检查覆盖，支持 HTML、Markdown、JSON 导出和确认删除。仍在更新的报告不能删除；删除维护报告不更改当前数据库或修复备份，旧修复记录若连同备份删除会单独说明。报告区分执行状态和诊断结论：成功检查发现异常仍是执行完成，未完成的检查与已确认的损坏分别说明。
- 报告逐项区分「WeQ 支持修复」「WeQ 不支持修复」及证据不足时的「可能支持修复」。没有页 HMAC 不代表数据库完好；明文库不受当前加密库重建工具支持，也不因此视为损坏。
- HTML／Markdown 导出直接包含已有修复记录中的前后体积、源库坏页与全零页、各阶段耗时及产物自检结果，不额外扫描；未取得的结果显示未知或未核验。普通进度最多每 2 秒保存一次完整报告，单库完成、失败及停止等关键状态立即保存，界面进度仍实时更新。
- QQ 专用 FTS 分词器在独立检查环境中不可用时，报告列出未核验的结构并显示部分完成，不把普通表通过当成整库全部正常；修复产物的复核也保留相同说明。
- 常规扫描、深度体检、修复及工具内的备份、恢复不创建任务列表条目，进度和结果在修复窗口内查看；关窗后修复仍在后台继续。
- 横幅统一只在主窗口显示，数据库修复、合成聊天记录等工具窗口不显示横幅。数据库修复进度只在修复窗口未获得焦点时推送，获得焦点即清除相关横幅，聚焦期间的完成结果也不补发；查看按钮直接返回对应数据库结果，不通过查看隐式重扫，新检查必须主动启动。正常体检进度与正常完成保持静默。
- 磁盘已满等原因导致报告暂时不能写入时，当前结果保留在内存并在页内提示，空间恢复后补存；未补存前不要退出应用。
- 数据库列表单行横向滚动，下面共用可折叠阶段时间线；最下方的检查结论、指标和问题明细单独放入「数据库检查详情」卡片，保持一致的内边距与对齐。当前阶段展开步骤、真实处理数量及对象；完成阶段可折叠，异常及未完成步骤保持可见。只有具体步骤有可靠分母时才显示百分比，账号只显示完成库数，不拼凑整体比例；总耗时仅显示一次，页扫描和文件读写在有可靠数据时显示当前速度。

### 空间与工作区位置 {#空间与缓存位置}

- 选中数据库后，分别显示工作区所在卷、原库卷的可用空间、预计新增峰值和建议预留空间；位于同一卷时合并为一项，按修复阶段的峰值计算。预计峰值包含未合并 WAL 可能带来的主库增长，建议值再加 25% 与每卷 64 MiB 缓冲；两者都不是最大占用保证。
- 空间不足或建议余量不足直接在页内显示警告卡片，列出「备份与修复工作区位置」、各卷可用空间和预计新增峰值，可刷新空间或更改位置。每个库实际开始修复时重新判断，低于预计峰值则返回「查看结果」而不是结束维护；只是建议余量不足时，可明确勾选接受风险后继续，不跳过备份或自检。取消确认、换库或换工作区位置后重新确认。
- 修复中持续检查剩余空间与本次临时文件实际占用，并按当前阶段计算后续写入、删除的峰值；已写完的文件不重复预留，后续释放只抵扣所在卷的预算，不用整轮总预估量与当前剩余空间比较。途中出现风险同样显示警告；不足以继续写入时中断未提交重建、清理本次临时件，保留锁和扫描结果以供处理后重试。
- 同一次持续维护中，提交前失败后的空间预检不再计入已成功备份的大小；备份仍占用磁盘，但当前可用空间已经反映这部分占用，重试只预留后续新增空间。更换工作区位置也会沿用原位置的成功备份。维护结束后不再复用；备份缺失、大小变化或内容校验失败时恢复完整备份预算，重新备份后再重建。
- 右上角设置按钮打开独立浮层，在「备份与修复工作区位置」更改备份和临时工作文件的位置，或恢复默认，维护页不再常驻显示路径。扫描、持锁等待期间也能调整，不需要放弃扫描结果；修复正在使用工作区时禁用更改。历史索引与报告保持原位，已有备份不会被自动迁移，仍可从原记录回滚。自定义目录失效时停止新修复，不创建替代目录。
- 新原生组件在重建完成后释放明文源副本，并直接生成带 QQ 头的加密产物；旧组件仍按较高的中间文件预算预检。最终临时产物始终留在原库同目录，以便安全替换。
- 备份优先尝试文件系统的独立写时复制克隆，不支持时正常复制；预检不依赖这部分节省。成功与失败的修复记录均按默认最近 3 份独立备份文件保留，多次重试共用的文件只算一份，历史记录和报告保留。删除单条旧记录不删除其他记录仍引用的备份；若最后一条引用的备份清理失败，保留记录供重试。主动清除共用备份时同步更新全部关联记录。
- 当前自定义位置下的修复数据也会计入存储管理，清除时需确认失去回滚能力并退出应用，不参与普通缓存清理。

### 布局迁移（旧版误修复的大库）

旧版 WeQ 在 1 GiB 以上的 QQ 库上可能把它误判成损坏，并用 standard SQLite 的页布局
「修复」出一个错位库：第 `262144` 页是真实数据，而 QQ 认为它是保留页。新版本不会在启动
时自动检查；**主动开始扫描**时才会读两个 4 KiB 页做判断：

- 文件不超过 1 GiB：不检查，直接按普通修复处理；
- 第 `262144` 页有数据、第 `262145` 页全零：判定为旧版误修复的 standard 布局，扫描结果记录此问题，修复时按 standard 源布局读取；
- 第 `262144` 页全零、第 `262145` 页有数据：QQ 布局，正常；
- 其它组合：不提示迁移。

布局迁移与普通修复共用同一条流程（备份 → 重建 → 替换 → 自检），区别是
按 standard 页号读出全部数据、再写回 QQ 布局。它复用本次扫描与维护锁，不额外重扫。失败时请以报告中的实际阶段与备份状态为准，旧版 native 不支持时会在替换前中止。

::: warning

修复目标在渲染层只用**库名**标识，目录、密钥、算法都在主进程解析 —— 这样接口不会变成任意
路径写入器。

:::

## 4. QQNT 抓包

非侵入式读网卡（**不注入、不改 QQ**）：TCP 重组 → MSF 帧切分 → 用该会话的 d2key 做 TEA 解密。
版式参考 reqable：左侧会话表（同一 `seq` 的发包 / 收包合成一行），右侧出该方向的
总览 / 解密数据 / 原始数据。

从 QQ 高级工具打开独立系统窗口，不替换设置页或侧栏；重复打开会聚焦原窗口并保留已捕获的数据。关闭抓包窗口或切换 WeQ 账号、数据源会释放该窗口持有的抓包会话；启动尚未返回时，迟到句柄会在返回后释放，不误停后来建立的会话。锁屏会隐藏窗口内容、暂停帧读取，已经开始的底层抓包仍保留，解锁后继续读取。

宽窗口左右分栏，窄窗口上下分栏；分隔条可拖动，也可聚焦后用方向键调整。账号选择、方向与关键字过滤、请求/响应明细、复制及 JSON/JSONL 导出保留在同一窗口。请在关闭前导出需要保留的帧；关闭窗口不保留未导出的临时列表。

- 顶部工具条选一个**在线账号** →「开始抓包」→ 可选暂停 / 继续 / 停止 / 清空；
- 过滤条可按方向（全部 / 发包 / 收包）+ 关键字（命令字 / seq）筛；
- 解密数据栏对正文自动按 protobuf → JCE → 去长度前缀的顺序解析成 `{tag: value}` 树；
- Windows 需先装 [Npcap](https://npcap.com/)；Linux/macOS 需要 root，会弹授权窗口把抓包
  会话放进临时提权子进程（WeQ 本体不以 root 运行）。
- macOS 自动端口模式要求带 PKTAP 进程归属的权限助手。旧助手会提示在设置中修复长期授权，避免混入同机其他 QQ 的连接；固定端口仍可用于单连接诊断，但不能据此宣称覆盖了所有连接。

### 导出

工具条的**「导出」**按钮把当前列表里**符合过滤条件**的帧（也就是眼前看到的这些）导出成文件，
下拉里选格式：

| 格式 | 内容 |
| --- | --- |
| **JSON** | 一份自包含文档 `{ meta, frames }`，每帧带 `decoded` 解析树与 raw / plain / body 的 hex |
| **JSONL** | 每行一帧，方便 `jq` / `grep` 流式处理 |

桌面端弹系统保存框、落到所选路径；Web 端写进服务端导出目录，当前窗口仍活动时触发浏览器下载。窗口关闭、切源或锁屏后才返回的结果不在旧文档触发下载，也不把旧路径回填到新来源。
导出结果会以一条提示（含帧数 / 体积 / 路径）反馈。

## 5. Protobuf / JCE 逆向

把 hex / base64 输入，按 **protobuf** 或 **JCE**（QQHook TarsParser 语义）解析为 `{tag: value}`
的简洁 JSON（对齐 CyberChef 的 Protobuf Decode）。**嵌套 message 会自动逐层展开**，不用再手动把
子字段的 hex 拿出来二次解析；`tag ≥ 1001` 的字段名直接跟在字段号后面显示。

顶部可切换两种视图：

- **简洁**（默认）：纯 JSON，只有字段号与值 —— 能当可读文本的 bytes 直接给字符串，其余给 `0x…` hex。
- **详细**：每个值旁再出现转换按钮，用于逐个值做旁路解读：

| 类型 | 可转换 |
| --- | --- |
| bytes | hex ↔ 文本 / Base64 / 按 protobuf 解析 / 按 JCE 解析（支持混合嵌套） |
| 整数 | 有符号 ↔ 无符号 / bool / 时间戳 / zigzag / hex |
| fixed64 / fixed32 | 整数 ↔ float |
| 字符串 | 文本 ↔ hex |

面板支持自动识别格式、复制结果、清空、载入示例。适合研究 QQ 协议里那些二进制字段。

::: info

MCP 的 `decode_blob` / `decode_db_blob` 也是同一套输出：纯 JSON `fields` 树（嵌套自动展开）
外加一个 `names` 图例，把树里出现过的 `tag ≥ 1001` 字段名单独列出来，避免字段名把数据树撑长。

:::

::: tip

**开头的长度前缀会自动识别并剥离**。抓包 / 内存里经常拿到形如 `00 00 00 D5 0A 08 …` 的字节：
前几字节是长度头，直接解析会让游标跑偏。解析器会枚举 4 / 2 / 1 字节 × 大端 / 小端，
只有「读出的值 = 整包或负载长度」**且**剥完能完整解析时才采用，所以不会硬编码「砍 4 字节」，
正常数据也不会被误削；命中时结果里会标出剥掉了什么。

:::

## 6. QQ 登录账号管理

管理**本机 QQ 的登录记录和设备标识**，数据来自 `login.db` 及设备标识文件。修改前需要退出所有 QQ 实例，重新启动 QQ 后核对结果；不需要重启 WeQ。

### 页面内容

- 顶部是本机**设备 guid**（服务端认设备的依据，可一键复制），旁边一枚「随机更换」；
- 下面每个账号一张卡片：头像 / 昵称 / QQ 号 + 「快速登录」徽章（该号在 `login.db` 里有缓存的
  a1）、上次登录时间，以及**数据目录还在不在**（只有登录记录、目录已经被删的号会标出来）。

### 三个动作

| 动作 | 做了什么 | 影响 |
| --- | --- | --- |
| **移除快登** | 清掉 `login.db` 里缓存的 a1（`[1004]`） | 账号行还在，但下次 QQ 启动它不再出现在快速登录列表，要重新输密码 / 扫码 |
| **删除账号** | 从 `login.db` 删除该账号的登录记录 | **不会删除聊天记录与账号目录**；不等于注销 QQ 账号，后续仍可重新登录 |
| **随机更换 guid** | 随机生成设备 GUID 并写回本机设备标识文件 | 改变后续请求使用的设备标识，可能影响设备识别或触发登录验证，请在重新启动 QQ 后核对 |

### 必须「所有 QQ 都退出」才能改

三个写操作都受同一条闸门约束：**检测到有 QQ 实例在运行就全部置灰**，页面上会写明原因。

因为 `login.db` 与设备标识文件（Linux `global/nt_data/msf/machine-info`、macOS
`machineid-info`、Windows `<msf>\Registry20`）都是 QQ 常驻读写并缓存在内存里的 —— 在线时改完
会被它覆盖回去（Windows 的硬件回退甚至会自动重写自己的缓存）。与其做一个静默失效的按钮，
不如要求先退出 QQ。实例数用 QQ 自己记的 `launcherCounts` 判断，不数进程。

::: info

换完 guid，WeQ 自己存的那份账号配置会一起同步（guid 与按旧 guid 解出来的 a1 payload 缓存），
所以之后从 WeQ 发起的快速登录 / 抓包 / 在线识别不会拿旧 guid 去冒充新设备。

:::

## 7. 自动策略与在线能力受限

「自动启用 QQ 在线能力」位于[设置 → 常规 → 在线能力与授权](settings.md)。它只控制自动尝试；关闭后仍可从受限详情手动请求当前来源的 QQ 在线能力，请求不保存到配置或备份，也不跨来源或宿主重启继承。是否可用以宿主当前运行态及 QQ 实际能力共同判断：

- 依赖在线实例的功能（其它设备的密钥、需要发包补齐的导出等）会明确提示不可用；
- 本地记录查看、本地文件导出、密钥扫描等不依赖在线 QQ 的功能仍可使用；涉及缺失媒体或在线记录的内容可能无法补全。

关闭自动策略不撤销本次已作出的手动请求，也不代替所有功能的网络设置。克隆、助手及其他 API 功能仍可能按各自配置访问服务商，使用前请核对对应页面的联网说明。
